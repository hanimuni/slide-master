# Mode: pyramid

Conclusion-first argumentation. State the answer, then support it with mutually-exclusive, collectively-exhaustive evidence — every claim earns its place, every number carries a comparison. For audiences who want the result before the process: executives, boards, investors, decision-makers.

---

## 1. Narrative skeleton

**Conclusion first**: each page's governing message (the §IX `Core message`, rendered under the topic title — [`report-craft.md`](../report-craft.md) §1) *is* the conclusion. The body develops the supporting arguments beneath it.

SCQA opening, pyramid body:

| Stage | Role | Where |
|---|---|---|
| Situation | establish shared context | cover / first 1-2 pages |
| Complication | the tension / problem | early pages |
| Question | the implicit question to resolve | transition |
| Answer | the recommendation, developed MECE | all body pages |

**Assertion governing messages** — the topic title names the subject; the governing message states the finding:

| Topic title | Weak governing message | Strong governing message |
|---|---|---|
| "Ⅰ-1. 시장 현황" | "시장 현황은 다음과 같음" | "국내 시장 전년 대비 23% 성장, 세계 평균의 두 배" |
| "Ⅰ-2. 확산 장애요인" | "여러 문제가 있음" | "세 가지 구조적 모순이 전면 확산을 가로막음" |
| "Ⅱ. 추진 방안" | "추진 방안" | "집중 → 확대 → 정착 3단계로 '28년까지 전 기관 확산" |

Wording rules: [`report-craft.md`](../report-craft.md) §2.

**Data never stands alone** — every figure pairs with a comparison (prior period / benchmark / competitor / target / rank) and a "so what". A bare number is an incomplete thought in this mode.

**MECE** — when decomposing (drivers, segments, options), branches are mutually exclusive and collectively exhaustive; parts sum to the whole (or label "Other").

**Peer sets** — pages (or blocks) under one parent claim form a peer set:
- **One parent question, one role**: every peer answers the same question in the same role — reasons with reasons, findings with findings, steps with steps.
- **One logical order per set**: deductive, chronological, structural, or comparative (strongest first). Never mix orders inside one set.
- **One grammatical form per set**: all noun-ending or all sentence-ending governing messages ([`report-craft.md`](../report-craft.md) §2).
- **Section dividers carry the claim**: a divider's subtitle states the section's key-line claim, not the method or data source.

**Storyline skeletons**: pick the matching report type in [`storyline-patterns.md`](../storyline-patterns.md) when no user outline exists.

## 2. Page-structure tendencies

- Topic title → governing message (the conclusion) → supporting evidence beneath.
- Each body page answers one question and states its own one-sentence conclusion in the governing message.
- Decomposition pages (driver tree / MECE breakdown / 2×2 matrix) carry the analytical load.
- Source line on every page with external data ([`report-craft.md`](../report-craft.md) §7).

> Page structure is a tendency, not a coordinate template. Card / tree / chart / KPI geometry lives in [`templates/charts/`](../../templates/charts/) — adapt those skeletons, do not reinvent. This mode decides *what argument each page makes*, not pixel positions.

---

## 3. Speaker-notes register

Conclusion-driven: the first sentence of each page's notes is the takeaway, then 2-3 supporting facts in flowing prose. Composed, authoritative. Every number paired with its comparison in the same sentence ("23% — nearly double the industry's 12%"). Spell percentages as words where the spoken form reads more naturally. (Common framework: [`speaker-notes.md`](../speaker-notes.md).)

## 4. Page skeleton example

```
Title:      "Ⅱ-2. 성장 동인"                                        ← topic label
Governing:  "신규 유치가 아닌 재구매가 성장을 견인 — 매출 증가분의 60%"   ← the conclusion
Body:       3 MECE arguments, each with one contextualized datum
Footer:     출처: 자료명(연도) | 덱 약칭 · 03/12
```
